Final Project

Summary

My main objective in this project was to investigate whether a Pokemon’s type could be predicted based of its base stats through Multinomial Logistic Regression modeling

My analysis showed that Pokemon types do display statistical patterns in their base stats. Certain types tend to perform better in specific attributes, like Steel and Rock types having higher defense or Electric and Flying types having higher speed. Dragon types also tended to have some of the highest overall stats. The Multinomial Logistic Regression model achieved an accuracy of around 25% for both primary and secondary type prediction. Although this accuracy may initially seem low, randomly guessing among 18 possible types would technically only achieve an accuracy around 5.6%. This suggests that Pokemon base stats does contain some important information related to Pokemon typing, which implies that there is patterns between base stats and types.

Motivation and Context

My investigation revolves around the Pokemon franchise, more specifically the statistical data of certain Pokemon in their mainline games. This statistical data consists of their health, attack, defense, special attack, special defense, and speed. This info determines the raw strength of a Pokemon along with the level they may be. Each Pokemon has a type, like fire and water and such. With a total of 18 types, there are many differences between each Pokemon. The purpose of types is to create variety and strategic advantages as some are stronger than others, some may be immune to others, and so on and so forth. Some Pokemon may even have two types, but I am mostly focusing on their primary type.

My initial thoughts were to determine if certain types tend to have a superior average total of stats. That was kind of simple so I delved into the idea that it may be possible that types might have patterns in their base stats, like rock types might have better defense. This eventually grew to our final idea, can we predict a Pokemon’s type based off stats?

So, I am investigating if we can predict a Pokemon’s primary type based off their base stats. This will be done by Multinomial Logistic Regression. Accurate predictions may very well imply that certain patterns exist between primary typing and base stats.

I am investigating out of pure curiosity and passion for Pokemon and to find out if I can truly apply what i have learned in class towards independent “research” and datasets. I do also find it interesting if we can get a somewhat accurate type predictor based of off base stats.

Data Description

An observation in this dataset presents a Pokemon as featured in their debut game, rather than any later appearances or alternate form (Deoxys). The various game stats data included are their base stats (HP, attack, defense, special attack, special defense, and speed) as featured in their debut game, along with a total base stat value, height, weight, Pokedex ID, and their generation id. There are 649 observations with 15 different variables.

This CRAN dataset was collected by William Amorim and published in 2023. Based on linked sources, I would assume stats data was collected from Bulbapedia, a reliable and community-driven online encyclopedia dedicated to the Pokemon franchise, and from a GitHub that hosts data for Pokemon as well. A separate GitHub was used to link to Pokemon images.

Indexing issues are caused by Mega Pokemon and by alternate versions of Pokemon, so I subsetted the dataset. Another reason for this was due to my lack of interest in the Pokemon past the 5th generation. So, Pokemon removed were any beyond the 5th generation. A few variables were removed too, such as 2 columns with urls that link to images, 3 columns that contained hex codes to their main colors, species id variable, and the 2 egg group variables. This is due to the fact that they will be useless here. The species id variable was removed since it was the same has the id variable, and egg groups are just irrelevant to my narrative. I also added a total stats variable that sums up all 6 of their base stats for a singular variable.

Modeling

As stated before, the model I selected was Multinomial Logistic Regression.

To summarize, Multinomial Logistic Regression is a classification model used when the response variable has more than two possible categories. In this project, the response variable is a Pokemon’s primary type, which contains many different possible outcomes. The model uses predictor variables to estimate the probability that an observation belongs to each possible class.

The predictor variables used in this model are HP, attack, defense, special attack, special defense, and speed. The model looks for statistical relationships between these base stats and Pokemon type patterns. For each Pokemon, the model calculates probabilities of being each possible type over some baseline type selected by the model, which is Bug here. The type with the highest probability becomes the prediction.

We first convert type_1 into a factor variable. Next, classification is set as its mode and the multinomial regression model is specified using the nnet engine. A recipe is then created to define the relationship between the response and predictor variables. We also normalize all the predictors in the recipe step. This basically rescales the predictors onto a similar scale so that no single variable dominates any other. Finally, the workflow combines the recipe and model before fitting the model onto the training data.

set.seed(67)

# Convert response to factor
pokemon_train$type_1 <- as.factor(pokemon_train$type_1)
pokemon_train$type_2 <- as.factor(pokemon_train$type_2)

multi_model <- multinom_reg(
  mode = "classification",
  engine = "nnet"
)

multi_recipe_1 <- recipe(
  type_1 ~ hp + attack + defense + special_attack + special_defense + speed,
  data = pokemon_train
) |>
  step_normalize(all_predictors())

multi_recipe_2 <- recipe(
  type_2 ~ hp + attack + defense + special_attack + special_defense + speed,
  data = pokemon_train
) |>
  step_normalize(all_predictors())

multi_wflow_1 <- workflow() |>
  add_model(multi_model) |>
  add_recipe(multi_recipe_1)

multi_wflow_2 <- workflow() |>
  add_model(multi_model) |>
  add_recipe(multi_recipe_2)

multi_fit_1 <- fit(multi_wflow_1, data = pokemon_train)

multi_fit_2 <- fit(multi_wflow_2, data = pokemon_train)

Conclusion

Overall, the main takeaway from this project is that Pokemon base stats do carry some information about typing, but not enough to make great accurate predictions on their own. From the EDA, we saw clear patterns between certain types and specific stats.

However, when it came to actually predicting a Pokemon’s primary or secondary type using Multinomial Logistic Regression, the results were limited. The model achieved around 25% accuracy, which is better than random guessing across 18 types, but still not strong enough to be considered reliable. This suggests that while base stats are related to type, they do not determine it.

One important reason for this limitation is that Pokemon typing is not based purely on base stats. Types are influenced by game design decisions and balance. Because of this, there is a lot of overlap between types and many different types can share similar stats. This makes it very difficult for a model to clearly identify and separate types using only base stats.

In conclusion, this project shows that there is a some relationship between Pokemon types and base stats. This relationship is strong enough to create patterns and slightly better than random predictions, but not strong enough for precise classification.

Limitations and Future Work

One of the main limitations is that base stats alone are not enough information to fully explain or predict Pokemon typing. Types are designed using a mix of gameplay balance, aesthetics, plot, and intended roles in battle, not just numerical stats. Because of this, we face a lot of overlap between types, which makes classification difficult for any statistical model.

Another major issue is class imbalance. Some types, such as Water and Normal, appear very frequently in the dataset, while others like Dragon or Ice appear much less often. This creates bias in both the model and predictions, since the model has far fewer examples to learn from for rare types. This is made visible in the confusion matrices, where the model tends to over-predict more common types and struggle with less frequent ones.

For reference in future work, I was made aware it was actually a great idea to include hp and weight into the model. However, direct plug in to the recipe wasn’t the best way to do it, and lack of time prevented me from truly exploring this idea. Time was a limitation, I am sure if I included these variables the right way, our prediction could have gotten a bit more accurate

As for the dataset itself, there is really no way to improve data collection, all the stats we need are in the data. I believe there are no ethical concerns about how this data was collected or how the results can be used. Information is picked up directly from the games from dedicated fans, and the analysis does nothing but maybe help a player strategize their playthrough in some way. This is due to the fact that this is just a nerdy and mathematical look into Pokemon, surely nothing crazy could happen.
